## Assumptions and open hosting questions

- Assumption: v0 has no login/user database/cloud saving; **no end-user authentication does not mean no service protection**. Existing `UseAuthorization()` alone establishes no private service boundary.
- Assumption: FastAPI remains reachable only by Backend. Actual deployment/network exposure is unknown, not confirmed safe or publicly exposed.
- **Hosting gate (High; Backend + AI/ML + Team Lead):** choose private/internal networking where possible. If internet-reachable, require HTTPS and suitable platform service-to-service protection before deployment; verify unauthorized direct calls fail and authorized Backend calls work. No OAuth/JWT framework is mandated here.
- Hosting questions: who owns ingress, service credentials/rotation, request/concurrency limits, log access/retention and production environment settings? How do platform timeouts fit the total preview budget? Decide before shared/public deployment, without infrastructure implementation in this review.
- Contract questions: where will approved OpenAPI and versioned taxonomy be published? What are the agreed development limits and Budget/duplicate-interest behavior? Backend and AI/ML jointly approve breaking schema changes; Data and consumers align mapping semantics. A Git taxonomy file alone will not prove deployed version agreement.
